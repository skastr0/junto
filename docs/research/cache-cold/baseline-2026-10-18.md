- For comparison, the **108 session-first calls** wrote 2,732,439 tokens (11.1%), about 25k per start. That is the cost a fresh session pays, and the cut swaps the gap turns for these.

## Method (rerun)

Run `python3 -I docs/research/cache-cold/measure.py --days 7` (add `--now <ISO>` to pin the window, or `--json` for machine output). The script reads every `~/.claude/projects/-Users-guilhermecastro-Projects-junto/*.jsonl` and `*/subagents/*.jsonl` modified inside the window. It takes `type == "assistant"` records that carry `message.usage`, and counts each API call once, deduplicated by `requestId` (falling back to `message.id`), because streamed chunks repeat the same usage. The call's time is its first chunk's timestamp. Each transcript file is one session, and a subagent's file is its own context. Calls are sorted by time. A call's gap is the time since the previous call in the same file, and that previous call may fall before the window. A call counts in a bucket when it is inside the window and its gap is over 5 or 60 minutes. The first call of a file has no gap and is counted separately as a session start. Tokens are `cache_creation_input_tokens`, split by `cache_creation.ephemeral_1h/5m_input_tokens`. The share divides by all cache_creation tokens of in-window calls. The worst 10 are the largest single cache_creation values among gap > 5 min calls. After the change, the >60 min bucket should shrink toward zero, and session starts should rise in count with a smaller cost per start.
